**Finding 1 (bug, high): the Log tab of Owner tools never shows the log; after about 7.5 s it shows "Something went wrong. Please try again."**
- Where: `src/web/src/core/services/ownerTools/ownerToolsService.ts` line 133 (`id: readText(fields, 'id', what)` in `parseLogEntry`) and line 44 (`id: string` in `OwnerToolsLogEntry`). The API contract `OwnerToolsLogRow` (`src/api/Kvit.Contracts/OwnerTools/OwnerToolsLogRow.cs`) has `long Id`, so the JSON answer has `"id": 4` (a number). `readText` throws on a number, the query retries (requests at 0, 1 and 3 s, answers all 200) and then shows the error.
- Steps: log in as admin, Settings, Owner tools, tap "Log" (any width, EN and MK, light and dark).
- What I saw: "Loading..." with three skeleton rows for about 7 s (three identical `GET /api/admin/tools/log?limit=50`, all 200 at 2.3, 3.3 and 5.3 s after the page opened), then "Something went wrong. Please try again." / «Нешто тргна наопаку. Обиди се повторно.» with a "Try again" button that fails the same way (`shots\t17-log-after-11s-360.png`, `t16-log-en-US-360.png`). The API itself is fine: it returned 4 entries with admin, action, target and reason (`G-log-api` in `t8_owner.json`).
- Why the unit test did not catch it: `ownerToolsService.test.ts` line 336 (`['id', 3]`) asserts that a numeric `id` is rejected, so the test pins the wrong behaviour.
- Suggested fix: read `id` with `readCount` and make the field a `number` (the key in the list), or make the API send a string; change the test at line 336 to accept a number and reject a text. Screens affected: only the Log tab.
