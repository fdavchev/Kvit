# Phase 11: Dashboard + Release 1 (report, 2026-10-16)

Branch `feat/11-dashboard`. Seven steps: the dashboard backend, the Home screen, the closing bar and toasts, the Phase 10 leftovers, a full 360 px pass, the code-review fixes and this close-out. Release 1 is done when Filip says it works for him on something real.

## What Phase 11 delivered
- **Home (layout C):** two boxes "You are owed" and "You owe" (MKD and EUR apart), a pinned "Needs you" bar with a count, the groups as cards, Recent activity (everyone's last 5 actions), and a "+" with a short list: "Add to <group>", "New One bill", "Another group…".
- **"Needs you" is answered on Home:** Confirm / Reject for payments, Confirm / Object for closing.
- **Backend:** `GET /api/dashboard` (totals, open and closing groups, needsYou, recentActivity, plusTarget) and `POST /api/me/active` (one `Active` usage event per user per UTC day). No migration.
- **Toasts** sit above the closing bar so they no longer cover its buttons.
- **Phase 10 leftovers** from BACKLOG, and a full 360 px pass of every screen in EN and MK, light and dark (764 snapshots) with its fixes.
- **Code-review fixes (this close-out):**
  - A person whose groups are all Finished no longer sees "No groups yet". Home shows a compact "No open groups right now" card with one New group button, above Recent activity. The full empty state stays only when there are no groups and no activity.
  - A refused Confirm or Reject on a Home payment card (any error, also no network) refetches the dashboard, so the stale card goes away.
  - Slash words («платил/а») stay unbroken only when they are 12 characters or fewer, so a long name can wrap.
  - The dashboard's closing "Needs you" rule reuses the roster's `ClosingConfirmers`, like the group query. Same behaviour, one rule.
  - **CI fix:** the test `Active_SecondCallTheSameUtcDay_AnswersNoContentAndWritesNoSecondRow` failed on every GitHub run. The tests of that class share one fake clock, a sibling test leaves it at 23:59:59 UTC, and the test's +5 minutes then crossed midnight. Which test ran first depends on the folder the test files run from, so it passed on Filip's PC and failed on GitHub. The test now moves the clock to 12:00 on the next day first. The app code was right and did not change.

- **Step 2 (backend), choices not pinned by Filip:**
  - `GET /api/dashboard` returns `totals` (owed and owe per currency, MKD first, positive numbers), `groups` (Open and Closing only, the caller's own signed balance per non-zero currency, newest first), `needsYou`, `recentActivity` (last 5 events of every group the caller is still in, deleted groups and left groups excluded, Finished groups included) and `plusTarget`.
  - `needsYou` order: closing items first (they run out in 24 hours), then payments, oldest first. A closing item shows `startedByName` = the owner's name; the owner never gets one; a member who confirmed no longer gets one.
  - `plusTarget` looks only at Open groups: the group of the caller's newest non-deleted expense that the caller added, else the Open group the caller joined last, else nothing. **Filip decided (2026-10-15): the "+" never opens a One bill** (it finishes by itself, and the "+" is for the group you keep adding to). Only normal groups count for both choices; with none, the list has no "Add to" item. The Step 2 code does not do this yet (it still allows a One bill): tests and the fix go into the Step 3 run. Rejected: allowing a One bill.
  - `POST /api/me/active` writes one `Active` row per user per UTC day. The server remembers today's counted users in memory (one day only, never grows) and the unique index is the last guard: a second insert at the same moment is treated as "already counted". `ClientRequestIdSaving` was renamed `DuplicateSaving` because it now reports both duplicate cases, each matched by its own index name. No migration.
  - Test helper: the two near-identical test gates became one `InsertGate` (`tests/Kvit.Api.Tests/Persistence/InsertGate.cs`).
